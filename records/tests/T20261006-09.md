# T20261006-09 — 접지 텔레옵 재시험 (DI 기록): 게이트 가설 기각, 과속(끌림) 뒤 출력 0 → OVER_LOAD

- **조건**: T20261006-07과 같음 + 패치 0003(DI 기록). `~/zero` rail_corr 1.003989. bag `data/tests/T20261006-09/bag`(233 s). 사용자 텔레옵(직진·후진·q/e 곡선·a/d 회전).
- **사용자 관측**: "이것저것 하다가 곡선 이동도 잘 했는데 또 좌·우회전이 안 된다".

## 결과

- **DI는 주행 내내 양쪽 0x14(게이트 닫힘)** → E-stop/CTRL 게이트 가설 **기각**(쪽마다 5 Hz 기록, 끊김 구간은 0.5~3 s).
- **163.5 s 오른쪽 ALARM+OVER_LOAD**(이번엔 오른쪽). 런치 종료 뒤 `reset_alarm`으로 해제.
- 명령 추종 실패(|실측−명령| > max(50 %, 15 rad/s)) 구간 31개. 대표 구간(107.5~113.9 s, `analysis` 표):
  - `q`(v 0.15, w +0.5 → 왼쪽 10.4 / 오른쪽 73.4 rad/s): **바깥쪽(오른쪽)은 정상 추종**(73 rad/s, Pico 1.1 A, effort 1.0 A). **안쪽(왼쪽)은 전류 0**(Pico 0.1 = 대기, effort 0.0). 안쪽 바퀴는 바닥에 끌려 44~63 rad/s(명령의 6배)로 돌다가, 그 뒤 명령보다 느린 3.9 rad/s에서도 출력 0이 계속됨(110.3~111.2 s).
  - `e`에서는 좌우가 바뀌어 같은 모습(안쪽 오른쪽 0 A, 끌려 39~66 rad/s).
  - 곡선이 끝나고 후진 명령(113.7 s)에도 양쪽 모두 수백 ms 출력 0.
  - T20261006-07의 141~144.7 s(오른쪽 3 s 출력 0)도 직전에 오른쪽이 명령보다 빨리 끌려 돌았던 직후(140.1 s: 명령 −2.4, 실측 +59.8)였다.
- **공통 순서**: ① 바퀴가 명령보다 빨리 돌게 됨(곡선 안쪽 끌림, 50 kg 관성 감속) → ② 그쪽 MD400 출력 0(제동 토크 없음) → ③ 명령보다 느려지거나 방향이 바뀌어도 수백 ms~3 s 출력 0 → ④ 갑자기 출력 복귀·전류 펄스(T-07: 20 ms 창에 −1.98 A) → OVER_LOAD. 속도 루프 적분 와인드업(과속 동안 쌓였다가 풀림)과 일치. 바퀴를 띄운 상태는 관성이 작아 과속이 거의 없어 드러나지 않았다.
- MD400 설정(읽기, 양쪽 같음): SLOW_START/DOWN 0, MAX_SS_TIME 15, MAX_RPM 3200, ENC_PPR 1000, HALL_TYPE 2, GAIN posP 15·spdP 300·spdI 315, USE_LIMIT_SW 1, UI_COM 1.
- 관련 기록: 이전 팀 08-12 "회생 과전압 없음 — **667 rpm/s 소프트 램프** 유효"; 09-03·09-05 접지 시험은 직진 위주, 알람 0. 현재 diff_cont 감속 한계 1.0 m/s²(≈2670 rpm/s), 텔레옵 손뗌 감속 0.6 m/s²(≈1600 rpm/s), 텔레옵 곡선 q/e는 반경 0.3 m(안쪽 바퀴 10 rad/s). 실행기 프로파일은 0.3 m/s²·1.0 rad/s²(≈800/600 rpm/s).
- **판정**: 실패(재현) / 열림. 원인 후보: MD400이 과속 바퀴에 제동을 못 걸고 속도 루프가 와인드업함. 급한 감속과 작은 반경 곡선이 이를 유발하고, 공기압 10 psi는 스크럽 저항을 키운다. 다음: 완만한 램프 설정 + 실행기 경로(직진·제자리·큰 반경 원)로 통제된 접지 시험.
