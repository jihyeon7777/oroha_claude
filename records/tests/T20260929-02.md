# T20260929-02 — ros2_control 첫 실물 주행 + 종료·크래시 정지 (세션 A, A7·A8 일부)

- **조건**: 바퀴 띄움, `robot.launch.py power:=false`(`setup/bg.sh`로 기동), `use_limit_sw 1`, FTDI latency 16 ms(A1 미적용), ws `d62e99b`.
- **A7 주행** (bag `data/tests/T20260929-02/bag`, 10.03 Hz):
  - 플러그인 로그: `motor_L slave_id=2 direction=-1`, `motor_R slave_id=1 direction=+1`, `USE_LIMIT_SW set to 1` — C1(xacro reverse) 수정이 실물 플러그인에서 확인.
  - 전진 0.1 m/s(3 s): motor_L +27.47 rad/s(sd 0.48), motor_R +27.47(sd 0.28) — 기대 +27.5(263 rpm). 좌회전 0.5 rad/s: L −31.17, R +30.80 — 기대 ∓31.0. T-05 방향과 결합하면 물리적으로 전진·좌회전이 맞음. effort 0.0~0.1 A(분해능 0.1 A).
  - 주기: read 56.2 ms(48~64) + write 31.8 ms = 약 88 ms, 과부하 시 104 ms 초과 경고(`Overrun detected`) — **FTDI 1 ms(A1) 필요**.
- **A8 종료·크래시**:
  1. 주행 중 런치 SIGINT(안전망 ON): 전 프로세스 정상 종료, `[oroha safety] … ok`, 양쪽 0 rpm.
  2. 주행 중 런치 SIGINT(안전망 OFF): 역시 0 rpm — **ros2_control 4.48은 정상 종료 때 하드웨어를 deactivate하고 플러그인이 stop+torque_off 실행**(로그). 재검토 C3⑤(`on_shutdown` 패치)의 전제는 틀림 → 패치 불필요.
  3. 주행 중 `kill -9 ros2_control_node`(안전망 ON): 런치가 사망 감지 → 양쪽 정지 ok, 0.5 s 시점 0 rpm.
  4. 같은 크래시(안전망 OFF): **양쪽이 262 / −260 rpm으로 계속 회전** → `oroha_md_stop`으로 정지. 안전망이 크래시 대비로 필수임을 확인.
  - 부수 관측: 런치 동작 중 `oroha_md_stop`(두 번째 마스터)을 실행하자 플러그인이 `short read` 5회 → ERROR → 컨트롤러 비활성(H8 위험 실증, 5회 실패 시 ERROR 경로 확인).
