# T20261006-07 — 첫 접지 텔레옵 (세션 B5): 한쪽 구동 끊김 + 왼쪽 OVER_LOAD 알람

- **조건**: 바닥 주행, 약 50 kg, 10 psi, `wheel_radius 0.003580`. preflight GO(`20261006T080101Z.json`), 런치 `imu:=true`(패치 0001·0002), `~/zero` 적용(rail_corr 1.004227). bag `data/tests/T20261006-07/bag`(296 s). 사용자가 터미널에서 `deadman_teleop`(0.15 m/s, 0.5 rad/s)으로 운전하고 E-stop은 손에 쥠.
- **사용자 관측**: "q(전진+좌)는 빠르고 e(전진+우)는 느리다", "곡선 주행 뒤로 좌·우 회전이 안 되고 우회전하면 후진한다".

## 분석 (`/dynamic_joint_states`, Pico 50 Hz, cmd_vel_out)

| 시각 (bag) | 현상 |
|---|---|
| 127.7 s | 오른쪽 읽기 1회 실패 → 즉시 재시도 성공(패치 0002), 주기 174 ms 1회 |
| **141.3~144.6 s** | **오른쪽 MD400이 구동 안 함**: 후진(−0.15 m/s)·좌회전 명령에 바퀴는 왼쪽에 끌려 −3.8 rad/s만 움직임. 오른쪽 전류는 대기 수준(0.08~0.13 A), MD400 내부 전류 0.0, status 0, 통신 정상(read_seq 0.1 s마다 증가) → 144.7 s부터 다시 정상 구동 |
| **149.4~151.5 s** (`q` 곡선 v 0.15, w +0.5) | **왼쪽 MD400이 구동 안 함**: 명령 10.4 rad/s인데 바퀴가 33 → 63 → 10 rad/s로 끌려 돎, 왼쪽 전류 0~0.15 A(대기). 오른쪽(바깥)은 1.0~1.23 A(교정 범위 1.2 A 상한) |
| 151.2~151.5 s | 왼쪽 20 ms 창 안 전류 펄스 +0.99 / +0.84 / **−1.98 A** |
| **151.7 s** | **왼쪽 status 0x11 = ALARM + OVER_LOAD** (status2 0x10, 라이브러리 미정의 비트) → 이후 왼쪽 구동 불가. 사용자의 "우회전 시 후진"(`d`: 오른쪽만 후진)·"e 느림"(왼쪽 빠름 필요)과 일치 |

- 141~145 s(오른쪽)와 149~151 s(왼쪽)의 "알람 없이 전류 0으로 공회전"은 E-stop을 눌렀을 때와 같은 신호다(T20260929-01: 전류 먼저 0, 알람 없음, 코스팅). E-stop 2NC의 한쪽 접점, 즉 그 MD400의 CTRL 6·8번 게이트가 순간적으로 열렸을 가능성이 가장 크다. 손에 쥔 E-stop의 반쯤 눌림, 케이블·커넥터 접촉 등이 후보다.
- 왼쪽 과부하는 게이트가 다시 닫히며 6배 속도로 끌려 돌던 바퀴를 갑자기 잡은 순간의 제동 전류로 보인다(가설). 스키드 곡선의 안쪽 제동 부하 자체가 원인일 가능성도 남는다.
- 바퀴별 가드(M2)는 이런 경우를 못 잡는다. 공회전하는 바퀴도 땅에 끌려 돌기 때문이다(속도 ≥ 2 rad/s).
- 그 밖: 바깥쪽 바퀴 1.23 A는 교정 범위 경계, 회전 중 공통 모드 영향은 미분석.

## 조치

- 런치 종료(안전망 양쪽 정지·토크 오프 ok) → 정지 상태 DI 둘 다 0x34(DIR·START_STOP 닫힘, ENC_B) → 왼쪽 `reset_alarm` → status 0x00.
- 신규 `oroha_di_watch`: 두 MD400의 DI·status를 20 Hz로 읽어 변화만 출력하고, 모터 명령은 보내지 않는다. E-stop 반쯤 누르기·케이블 흔들기로 한쪽 게이트만 열리는지 확인할 준비.
- **판정**: 중단 / 열림. 접지 주행은 원인 확인 전까지 보류.

## 후속 (같은 날)

- 사용자 확인: 운전 중 E-stop에 손가락을 얹지 않았고, 케이블·커넥터 흔들림도 없음 → 손·케이블 가설은 약해짐.
- 패턴: 끊긴 쪽은 늘 **반대쪽이 큰 전류를 쓰던 때**였다(141 s 왼쪽 0.7 A → 오른쪽 끊김, 149~151 s 오른쪽 1.0~1.2 A → 왼쪽 끊김). 띄운 시험은 좌우 전류가 비슷해 이런 일이 없었다. 이전 팀 보고(`ctrl-stop-input-blocks-reverse.md`)에 따르면 `USE_LIMIT_SW=1`이면 CTRL 6·8번이 방향별 리밋처럼 동작한다. 두 MD400의 게이트 공통선이 E-stop 결선으로 묶여 있다면, 한쪽 모터 전류가 클 때 반대쪽 입력이 순간 "열림"으로 읽힐 수 있다(가설, 미확인).
- **패치 0003**(`0003-di-state-interface.patch`): `<joint>/di` 상태 인터페이스. PID_DI를 주기마다 한쪽씩 읽고, 실패해도 통신 오류로 세지 않는다. 실물 확인: 양쪽 0x34, `/dynamic_joint_states` 10 Hz 유지, 과주기 없음.
- 실행기: 주행 중 한쪽이라도 게이트가 0.25 s 넘게 열리면 FAIL("E-stop pressed" 또는 "one-side gate drop"). 가드에 **NOT_TRACKING**(|실측 − 명령| > max(50 %, 15 rad/s)가 1.5 s) 추가 — 끌려 도는 바퀴를 잡는다. FAIL 문구에 DI와 "CTRL gate open on …" 힌트. 추출 `joint_diag`에 `<joint>_di`, `gate_open_samples`. 테스트 추가(가드 21개 통과).
- 다음: ① 정지 상태에서 E-stop을 천천히 눌러 두 접점이 열리는 순서·DI 확인 ② DI를 기록하며 접지 텔레옵 재시험 — 구동이 끊길 때 그쪽 DI가 떨어지는지.
