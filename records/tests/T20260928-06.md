# T20260928-06 — E1 E-stop 특성 (세션 A, A6) — 실패: E-stop이 모터를 세우지 못함

- **목적**: 운용 설정(`USE_LIMIT_SW 0` — 왼쪽 reverse 바퀴의 음수 명령을 위해 필수)에서 E-stop이 모터를 세우는지, 해제 시 재출발하는지.
- **조건**: 바퀴 띄움. id 1(오른쪽), `oroha_direction_check --id 1 --rpm 500 --sec 10` (명령 1회, 실행 전 `USE_LIMIT_SW` 0 확인), ENC_PPR 1000, USE_EPOSI 0. 사용자: 회전 시작 약 3 s 뒤 E-stop 누름, 약 3 s 뒤 해제.
- **관측** (`T20260928-06/direction_20260928T091339Z.json`, 09:13:39Z): 10 s 내내 500 rpm 유지 — 1 s 이후 최소 487·최대 510 rpm, 정지 구간 없음, status 0(알람 없음), MD400 전류 0.1~0.2 A 일정, 위치 +2492 counts(10 s 연속 회전 이론 2500). **사용자 보고: E-stop을 눌렀으나 "안 멈췄음".** 시험 후 읽기: 양쪽 `PID_DI` b4(START_STOP 입력) = 닫힘(해제 상태), `USE_LIMIT_SW 0`.
- **해석**: 이전 팀 현장 보고(`ctrl-stop-input-blocks-reverse.md`): E-stop은 CTRL 8번(START_STOP, DI b4)에 결선돼 있고 **`USE_LIMIT_SW=1`일 때만 모터를 세운다**; 08-09 정지 성공은 `USE_LIMIT_SW=1`(공장값) 상태. ros2_control 플러그인은 configure 때 `use_limit_sw 0`을 쓰므로 **ros2_control 운용 중에는 E-stop이 작동하지 않는다**(이전 팀 twin 설정도 같음). 확인 필요: E-stop 누름·해제 시 DI b4가 바뀌는지(무동작 읽기 시험).
- **판정**: **실패 / 열림 — 치명.** 계획 규칙에 따라 모든 모터 작업 중단. E-stop을 전원 차단 방식 등으로 고치기 전에는 주행 시험 금지.

## T-06b 결선 확인 (무동작, 09:2xZ, `T20260928-06/di_poll_*.json`)

- 20 s 동안 두 MD400의 `PID_DI`를 ~31 Hz로 읽는 중 사용자가 E-stop 누름(시작 시 이미 눌림)→해제. 눌림: id1 DI 96(b5·b6만), id2 DI 0. 해제(t=1.25 s, 두 대 같은 표본): id1 116, id2 20 — **b4(CTRL 8, START/STOP)와 b2(CTRL 6, DIR)가 함께** 바뀜. b5·b6은 엔코더 A/B.
- v1.4.0 매뉴얼 README "Stop input (CTRL connector)": 6번(DIR)은 음수(CW), 8번은 양수(CCW) 방향을 허용하는 게이트이고, 둘을 한 NC 접점으로 GND에 묶는 것이 권장 결선, twin은 2극 NC(컨트롤러당 한 극). `USE_LIMIT_SW = 0`이면 CTRL 입력을 **무시**. 해제하면 다음 명령에서 즉시 재기동(ros2_control은 매 주기 명령). v8.6은 엔코더와 함께 사용 가능.
- **결론**: E-stop 결선은 이미 매뉴얼 권장 방식(두 게이트 모두)이다. 실패 원인은 `USE_LIMIT_SW 0` 운용값. 이전 팀의 "`USE_LIMIT_SW 1`이면 음수 명령 차단"(07-29)은 8번만 결선돼 있던 때의 결과(당시 DI b2 "계속 low")로 보인다 → `use_limit_sw: 1`이 올바른 운용값일 가능성. **검증 필요**(띄운 상태): `USE_LIMIT_SW 1`에서 ① 양수·음수 명령 모두 회전, ② 두 방향 모두 E-stop으로 정지, ③ 해제 시 거동(명령 1회 vs 재전송).
