# T20260929-04 — 주기(FTDI 1 ms) + ros2_control 운용 중 E-stop + RS485 분리 (세션 A, A8 나머지)

- **조건**: 바퀴 띄움, `use_limit_sw 1`, FTDI latency **1 ms**(사용자 설치 스크립트 적용 확인: udev 규칙 14:31, rviz_imu_plugin), `robot.launch.py power:=false`(`setup/bg.sh`), ws `e04ebe4`.
- **주기**: 전진 3 s 중 read 35.8 ms(35.3~36.3) + write 27.9 ms = **약 64 ms**(16 ms 때 88 ms·최대 104 ms). 10 Hz 여유 약 36 ms.
- **시험 1 — 주행 중 E-stop** (bag `data/tests/T20260929-04/bag_estop`): 0.1 m/s 15 s 명령. 3.51 s 회전 시작 → 6.21 s 정지(E-stop) → 11.81 s 해제와 함께 재출발(명령 계속) → 18.81 s 정지(명령 종료 + 0.5 s 타임아웃). 통신 오류 0, 하드웨어 active 유지.
- **시험 2 — 주행 중 RS485 분리** (bag `bag_unplug`, launch.log 293~318행): 분리 즉시 `Input/output error`, 약 0.4 s에 5회 실패 → ERROR → 하드웨어 `unconfigured`, 컨트롤러 비활성. **사용자 관측: 분리 후 바퀴가 E-stop을 누를 때까지 계속 돎, E-stop으로 정지.** 재연결 시 FTDI가 `ttyUSB2`로 재열거, `/dev/oroha_md400` 링크·latency 1 ms 자동 적용. 런치 종료 → 안전망이 새 포트로 양쪽 정지 ok, `oroha_md_stop` ALL STOPPED, 0 rpm.
- **판정**: 통과 / 종결. 문서화된 위험 확인: 통신 두절 시 MD400은 마지막 명령을 유지하고 **E-stop만이 멈춘다**. 복구 절차(E-stop 유지 → 재연결 → 런치 종료 또는 `oroha_md_stop` → 해제 → 재기동) 입증.
